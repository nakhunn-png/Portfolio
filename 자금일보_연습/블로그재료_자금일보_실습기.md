## 1. 계기: 영상 한 편

AX 회계사 해니의 영상에서, Claude Cowork에 은행 거래내역을 연결해 **매일 아침 자동으로 자금일보 대시보드가 만들어지는 흐름**을 봤다.

영상의 구성은 다음과 같았다.
- 은행 데이터를 가져오는 MCP 연결 (영상에서는 그리디·클로브 같은 도구)
- 매일 정해진 시간에 도는 **루틴** (데일리 작업)
- 결과를 보기 좋게 만드는 **대시보드 스킬**

"자동화하려면 뭐가 필요하지?"부터 물어봤다. 정리하면 세 가지다.

| 필요한 것 | 역할 | 비유 |
|---|---|---|
| 데이터 연결 (은행 거래내역) | 매일 새 거래를 가져온다 | 재료 |
| 분류 규칙 (자금코드 표) | 거래마다 이름표를 붙인다 | 레시피 |
| 스킬 + 루틴 | 정해진 시간에 같은 방식으로 만든다 | 요리사 + 알람 |

하지만 영상만 봐서는 **"그래서 자금일보가 정확히 뭘 계산하는 건데?"**가 손에 잡히지 않았다. 그래서 직접 해 보기로 했다.

## 2. 스킬 설치하기

영상의 스킬이 GitHub에 공개되어 있어서 그대로 설치했다.

```bash
git clone https://github.com/hany202507/finance-ai-skills.git
cp -r finance-ai-skills/skills/자금일보 ~/.claude/skills/
```

설치된 스킬 폴더의 구성은 다음과 같다.

```
자금일보/
├── SKILL.md              ← 스킬 설명서 (언제, 어떻게 쓰는지)
├── scripts/build.py      ← 실제 계산 프로그램 (pandas만 사용)
├── assets/template.html  ← 대시보드 화면 틀
├── assets/분류규칙_예시.md ← 자금코드 분류표 예시
├── examples/             ← 예시 회사 데이터
├── tests/
└── requirements.txt
```

스킬이 지키는 규칙 (SKILL.md 요약):
1. **계좌 간 이체는 입금·출금에서 뺀다.** 내 왼쪽 주머니에서 오른쪽 주머니로 옮긴 돈이기 때문이다.
2. **전일 잔액 + 입금 − 출금 = 계좌 잔액 합계**를 날마다 1원까지 검산한다. 하루라도 안 맞으면 **멈춘다.**
3. 자금코드는 **분류규칙.md 표로만** 붙인다. 표에 안 걸린 거래는 **"확인 필요"**로 따로 모은다.
4. 입출금 예정표가 있으면 **앞으로 2주 예측**과 **큰 출금**을 붙인다.

프로그램 실행 결과 코드: `0` 통과 / `1` 입력 오류 / `2` 검산 실패.

## 5. 엑셀 수동 실습: 한 단계씩

엑셀에서 `bank_transactions.csv`를 열고 시작했다.

**시트 배치** (독자가 따라 하기 쉽도록 고정)
- A~L열: 원본 거래내역 (2행~154행, 153건)
- M열: 내가 붙이는 자금코드 (5단계)
- O열: 항목 이름, P열: 계산 값, Q열: 수식 확인용
- **P1: 보고 싶은 날짜** ← 이 칸만 바꾸면 모든 계산이 따라 바뀐다

### 1단계. 데이터 둘러보기

- 마지막 거래 번호: **TX0153**
- 숫자(입금·출금·잔액)는 **오른쪽 정렬**이다. 왼쪽 정렬이면 엑셀이 숫자를 글자로 읽은 것이니 계산이 안 된다.

### 2단계. 시작 잔액 구하기

`bank_accounts` 시트를 같은 파일로 가져왔다 (시트 탭 우클릭 → **이동/복사**).

```
=SUM(F2:F4)
```
→ **1,890,700,000원** (9/30 통장 3개 합계)

> **스스로 답해 본 질문**
> 1. 시작 잔액은? → 1,890.7백만 원
> 2. 가장 돈이 많은 통장은? → 우리은행. 매출대금과 매입대금을 관리하는 주거래 계좌라서.
> 3. 통장마다 용도(purpose)가 있으면 좋은 점은? → **"용도만 보고도 무슨 돈이 오가는지 짐작할 수 있고, 평소보다 크게 들고 난 금액을 찾기 쉽다."**

### 3단계. 하루 입금·출금 합계 (SUMIFS)

SUMIFS의 뜻: **"이 열에서, 조건에 맞는 줄만 골라 더해라."**
```
=SUMIFS(더할 열, 조건을 볼 열, 조건)
```

| 항목 | 수식 |
|---|---|
| 그날 입금 | `=SUMIFS(I:I, E:E, P1)` |
| 그날 출금 | `=SUMIFS(J:J, E:E, P1)` |
| 그날 거래 건수 | `=COUNTIFS(E:E, P1)` |

**10/1 결과**: 입금 70,748,300 / 출금 50,379,900. (10/1에 거래가 있는 통장은 우리은행 하나뿐이다. 농협과 기업은행은 거래가 없다.)

> 💡 **FORMULATEXT**: 옆 칸에 `=FORMULATEXT(P2)`를 쓰면 P2의 수식이 글자로 보인다. 수식을 공부하거나 블로그에 캡처할 때 편하다.

### 4단계. 전일 잔액과 검산: 자금일보의 핵심 한 줄

```
전일 잔액 + 입금 − 출금 = 당일 잔액
```

**전일 잔액**: 시작 잔액에 "P1 날짜 **전까지**"의 입금은 더하고 출금은 뺀다.
```
=bank_accounts!$F$2+bank_accounts!$F$3+bank_accounts!$F$4
  + SUMIFS(I:I, E:E, "<"&P1) - SUMIFS(J:J, E:E, "<"&P1)
```
- `"<"&P1` = "P1 날짜보다 작은(이전) 날짜"라는 조건. `&`는 글자 `<`와 날짜를 이어 붙인다.

**당일 잔액 (계산)**: `=전일 잔액 + 입금 − 출금` (예: `=O6+O7-O8`처럼 칸을 더하고 뺀다)

**당일 잔액 (통장 실제 값)**: 통장별로 "그 날짜까지의 **마지막 거래**의 balance"를 가져와 세 개를 더한다. (아래 LOOKUP 설명 참고)

**검증**: `=계산 잔액 칸=실제 잔액 칸` → **TRUE**면 통과.

P1 날짜를 아무 날로 바꿔도 TRUE가 나오는 것을 확인했다.

#### 🚧 시행착오 ①: LOOKUP이 갑자기 너무 어려웠다

처음에 통장 실제 잔액을 가져오는 수식을 이렇게 한 번에 받았다.
```
=IFERROR(LOOKUP(2,1/(($B$2:$B$154="A1")*($E$2:$E$154<=$P$1)),$K$2:$K$154),bank_accounts!$F$2)
```
그대로 따라 쳐서 답은 맞았지만, 솔직히 **무슨 뜻인지 하나도 몰랐다.** "갑자기 너무 급 어려워졌는데?"라고 말하고 다시 배웠다.

**다시 배운 방법: 도우미 열로 쪼개기**

① M열에 "이 줄이 A1 통장이면서, P1 날짜 이전(같은 날 포함)인가?"를 TRUE/FALSE로 적는다.
```
=AND(B2="A1", E2<=$P$1)
```
② "TRUE인 줄 중 **마지막 줄**의 잔액(K열)"을 가져온다.
```
=LOOKUP(2, 1/M2:M154, K2:K154)
```

**왜 이게 되나? "마지막으로 손 든 학생" 비유**
- `1/TRUE` = 1, `1/FALSE` = 오류. 그러면 조건에 맞는 줄만 **"1"(손 든 학생)**이 되고, 나머지는 오류(손 안 든 학생)가 된다.
- LOOKUP에게 "2를 찾아라"라고 시키면, 2는 어디에도 없다. 그러면 LOOKUP은 **마지막으로 손 든 학생(마지막 1)**에서 멈춘다.
- 그 줄의 잔액 = **그날까지의 마지막 잔액**.

③ 이해한 다음 긴 버전과 비교했다. 도우미 열 대신 괄호 안에서 조건 두 개를 곱한 것(`*` = 그리고)뿐이다. 거래가 하나도 없어 오류가 나면 `IFERROR`가 9/30 시작 잔액을 대신 넣는다.

> **배운 점**: 어려운 수식은 **도우미 열로 쪼개서 먼저 눈으로 확인**하고, 그다음에 한 줄로 합치면 된다. (10/30 기준 도우미 열로 가져온 A1 잔액 = 2,310,922,500)

### 함정 ①: 계좌 간 이체 빼기

10/19를 넣어 보니 입금이 **318,232,400**, 출금이 **502,665,500**으로 이상하게 컸다.

원인은 **TX0084, TX0085**였다. 기업은행에서 우리은행으로 옮긴 250,000,000원이 출금과 입금에 **둘 다** 잡혔다.

> 내가 쓴 표현: **"왼주머니를 오른주머니로 옮겼네. 누가 보면 매출과 비용이 크게 늘어난 것처럼 보임."**

적요(G열)에 "내부이체"가 **없는** 줄만 더하도록 조건을 하나 더 붙였다.
```
=SUMIFS(I:I, E:E, P1, G:G, "<>*내부이체*")
=SUMIFS(J:J, E:E, P1, G:G, "<>*내부이체*")
```
- `<>` = 아니다, `*` = 앞뒤에 아무 글자나. 즉 **"내부이체라는 단어가 들어 있지 않은"**.

| 날짜 | 이체 포함 입금 | 이체 제외 입금 | 이체 포함 출금 | 이체 제외 출금 |
|---|---:|---:|---:|---:|
| 10/13 | | 78,177,900 | | 694,800 |
| 10/19 | 318,232,400 | **68,232,400** | 502,665,500 | **252,665,500** |
| 10/21 | | 99,047,300 | | 1,062,500 |

10/19 잔액: 전일 2,607,169,900 → 당일 **2,422,736,800**. 이체를 빼도 넣어도 **잔액은 똑같다.** 입금과 출금에서 같은 금액이 빠지기 때문이다.

> 내가 내린 결론: **"산식을 보면 당연함."** 이체는 잔액을 바꾸지 않고, 입출금 규모만 부풀린다.

#### 🚧 시행착오 ②: 오타 하나로 결과가 틀렸다

```
=SUMIFS(I:I, E:E, P1, G:G, "<>*내부거래*")   ← 틀림
=SUMIFS(I:I, E:E, P1, G:G, "<>*내부이체*")   ← 맞음
```
데이터에는 "내부**이체**"라고 적혀 있는데 "내부**거래**"로 쳤다. **엑셀은 오류를 띄우지 않고 조용히 틀린다.** 조건 글자는 반드시 실제 데이터에서 복사해 오자.

### 5단계. 자금코드 손으로 붙이기 (M열)

자동 분류 대신, 분류규칙 표를 보면서 **필터로 직접** 붙였다.

1. G열(적요) 필터에서 예: "매출대금"이 들어간 것만 고른다.
2. 보이는 M열 칸을 모두 선택하고, `매출대금 회수`를 입력한 뒤 **Ctrl + Enter** → 보이는 칸에 한 번에 들어간다.
3. 규칙 순서대로 반복한다. **내부이체 먼저.**

마지막에 M열 필터 목록으로 확인했다. **빈칸 포함 고유값 12개**, 빈칸은 **2건**이다.
- TX0109: 10/22 보증금 반환 (주)한빛물류 +5,000,000
- TX0146: 10/29 타행송금 김*영 −2,350,000

> **이 2건을 "확인 필요"로 두는 이유 (내 답)**
> 1. 예외 거래라서. 일상적인 거래로 보기 어렵다. 아주 가끔 있거나 설명이 부족하다.
> 2. 처리 방법:
>    - **보증금 반환**: 은행 조회서, 그리고 (주)한빛물류에 회사 명의로 조회서를 보내되 회신처를 회계법인으로 해서 감사로 확인한다.
>    - **타행송금 (김*영)**: 일단 자금팀장에게 물어 소명을 듣는다. **가지급금일 가능성**도 있다.

#### 🚧 시행착오 ③: 자금코드 이름이 제각각

처음엔 `카드결제대금(출금)`처럼 괄호를 붙이거나, 부가세 납부를 `세금과공과`로 적었다.

- 같은 코드는 **글자가 완전히 같아야** SUMIFS가 모아 준다. 이름을 통일했다.
- **자금코드는 회계 계정이 아니다.** 부가세 납부는 비용(세금과공과)이 아니라, 받아 둔 부가세(**부가세예수금, 부채**)를 국가에 넘기는 것이다. 그래서 "세금·4대보험"이라는 **돈의 흐름 이름**으로 묶는다.

#### 🚧 시행착오 ④: 엑셀 조작에서 막힌 것들

- **필터 범위가 계산 칸까지 먹었다** → A1을 선택하고 필터를 다시 걸었다.
- **코드 목록 중간에 빈 줄** → 행 전체를 지우면 같은 행의 거래(TX0023)까지 사라진다. **O24:R24 칸만 선택 → Ctrl + − → "셀을 위로 밀기"**.
- **Ctrl + Shift + 1(쉼표 서식)을 누르면 "i"가 쳐졌다** → 윈도우의 **입력 언어 전환 단축키와 겹친 것.** 대신 **Alt → H → K**를 순서대로 누르거나 홈 탭의 쉼표(,) 버튼을 쓴다.
- **함수 이름 오타** `counifs` → `COUNTIFS`. 함수를 칠 때 **자동완성 목록에서 고르고, 이름이 대문자로 바뀌는지** 보면 오타를 잡는다.

### 6단계. 자금코드별 합계표

O19부터 자금코드 목록을 놓고, 날짜(P1) **그리고** 코드가 같은 것만 더했다.
```
P19: =SUMIFS($I:$I, $E:$E, $P$1, $M:$M, O19)   ← 입금
Q19: =SUMIFS($J:$J, $E:$E, $P$1, $M:$M, O19)   ← 출금
R19: =COUNTIFS($E:$E, $P$1, $M:$M, O19)        ← 건수
```
- `$`는 **"아래로 복사해도 이 칸은 고정"**이라는 뜻이다. 날짜 칸(P1)과 열 전체는 고정하고, 코드 칸(O19)만 한 칸씩 내려간다.
- 빈칸(확인 필요) 합계는 조건에 `""`를 넣는다: `=SUMIFS($I:$I, $E:$E, $P$1, $M:$M, "")`

**10/22 검산**

| 자금코드 | 금액 | 건수 |
|---|---:|---:|
| 매출대금 회수 (입금) | 80,480,000 | 2 |
| 카드매출 정산 (입금) | 7,386,400 | 1 |
| 원재료 매입 (출금) | 37,060,000 | 1 |
| 운영비 (출금) | 475,100 | 2 |
| **확인 필요** (보증금 반환, 입금) | 5,000,000 | 1 |

마무리로 합계 줄(`=SUM(P19:P29)` 등)과 검증 줄(`=P30=P2`)을 넣으면, 코드별 합계가 하루 합계와 맞는지 바로 보인다. (단, 건수 검증은 이체가 있는 날 FALSE가 된다. 하루 건수에는 이체가 들어 있기 때문이다.)

## 6. 입출금 예측의 원리 (엑셀 실습은 다음 편)

스킬의 대시보드에는 **앞으로 2주 예측**이 있다. "지금까지 거래만으로 미래를 어떻게 알지?" 싶었는데, 원리는 **일기예보**와 같았다.

### 원리 4줄

1. **확정된 약속은 그대로 쓴다** (예정표 `cash_schedule.csv`) → 예: "11/3 바다수산에 72,500,000 지급"
2. **매일 반복되는 건 최근 평균으로 짐작한다** → 최근 20영업일 합계 ÷ 20, 10만 원 단위로 반올림
3. **같은 종류가 예정표에 있으면, 그날은 평균을 빼고 예정만 쓴다** (중복 방지)
4. **잔액은 자금일보 공식 그대로 이어 붙인다**: 어제 예상 잔액 + 예상 입금 − 예상 출금

휴일에 걸린 예정은 다음 영업일로 미룬다. 계좌 간 이체 예정은 예측에서도 뺀다.

### 확정된 입출금 (예정표에서)

- **입금 145,200,000**: 11/2 한결마트 84,000,000 / 11/5 도담급식 61,200,000
- **출금 129,700,000**: 11/3 바다수산 72,500,000 / 11/10 원천세 14,900,000 / 11/10 국민연금·건강보험 18,300,000 / 11/13 신한카드 24,000,000
- **제외**: 11/10 내부이체 40,000,000 (A1 → A2)
- 11월 급여(25일 전후)는 예측 기간(14일, 11/13까지) 밖이라 예정표에 없다.

### 평균 추정 (10/2~10/30, 20영업일)

| 묶음 | 포함 코드 | 하루 평균 (약) | 이 날은 평균을 쓰지 않음 |
|---|---|---:|---|
| 매출대금 회수 | 매출대금 회수 + 카드매출 정산 | 78,400,000 | 예정표에 매출대금이 있는 날 |
| 원재료 매입 | 원재료 매입 | 27,200,000 | 예정표에 매입대금이 있는 날 |
| 운영비 | 운영비 | 1,300,000 | (항상 평균 사용) |

### 손으로 해 본 예시

| 날짜 | 예상 입금 | 예상 출금 | 예상 잔액 |
|---|---|---|---:|
| 10/30 (실제) | | | 2,895,280,500 |
| 11/2 | 84,000,000 (예정, 평균 대신) | 27,200,000 + 1,300,000 = 28,500,000 | **2,950,780,500** |
| 11/3 | 78,400,000 (평균) | 72,500,000 (예정, 평균 대신) + 1,300,000 = 73,800,000 | **2,955,380,500** |

**예측의 목적**은 정확한 숫자 맞히기가 아니라, **돈이 모자라는 날을 미리 찾는 것**이다. 평균은 어디까지나 짐작이다.

> **다음 편 예고**: 예정표를 시트로 가져와 평균 3개를 SUMIFS로 구하고, 11/2~11/13 날짜별로 "예정 + 평균 − 중복"을 계산해 예상 잔액을 이어 붙여 본다. 모자라는 날이 있는지 확인하는 것까지.

## 7. 해 보고 느낀 점 (글 마무리용 재료)

- **자금일보는 결국 한 줄이다.** 전일 잔액 + 입금 − 출금 = 당일 잔액. 나머지는 모두 이 한 줄을 믿을 수 있게 만드는 장치다.
- **검산이 있어야 자동화를 믿을 수 있다.** 스킬이 "1원이라도 안 맞으면 멈춘다"는 원칙을 가진 이유를 손으로 해 보고서야 알았다.
- **계좌 간 이체는 잔액은 안 바꾸고 규모만 부풀린다.** 빼지 않으면 매출·비용이 커 보이는 착시가 생긴다.
- **"확인 필요"가 사람의 일이다.** 자동화는 분류표에 있는 것만 처리하고, 예외는 사람에게 넘긴다. 조회서, 팀장 소명, 가지급금 검토처럼 판단이 필요한 일이 남는다.
- **자금코드 ≠ 회계 계정.** 부가세 납부는 비용이 아니라 부채(부가세예수금)를 갚는 돈의 흐름이다.
- **AI 결과를 그대로 받지 말고, 이해 못 한 수식은 다시 묻자.** "그대로 따라 친 거라 나도 몰라"라고 말한 덕분에 도우미 열로 쪼개서 배울 수 있었다.
- **자동화 전에 수동으로 한 번.** 손으로 해 봐야 자동 결과가 맞는지 틀린지 판단할 수 있다.

## 부록 B. 이번 실습에서 쓴 엑셀 도구

| 도구 | 쓴 곳 |
