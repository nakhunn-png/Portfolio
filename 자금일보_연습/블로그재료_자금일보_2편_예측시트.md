## 1. 지난 편 요약과 이번 편의 질문

1편에서는 자금일보의 한 줄 공식을 153건의 거래로 검산했다.
```
전일 잔액 + 입금 − 출금 = 당일 잔액
```

자금일보 스킬의 대시보드에는 **앞으로 2주 입출금 예측**도 있다. 그런데 **"지난 거래만 가지고 미래를 어떻게 알지?"** 이번 편은 이 질문에서 시작한다.

## 2. 원리: 일기예보와 같다

| 원리 | 내용 |
|---|---|
| ① 확정된 약속은 그대로 | 입출금 예정표(`cash_schedule`)에 있는 건 날짜와 금액 그대로 쓴다 |
| ② 매일 반복되는 건 평균으로 | 최근 20영업일 실적 ÷ 20, 10만 원 단위 반올림 |
| ③ 겹치면 약속만 | 같은 종류의 예정이 있는 날은 평균을 쓰지 않는다 (두 번 세기 방지) |
| ④ 잔액은 이어 붙이기 | 어제 예상 잔액 + 예상 입금 − 예상 출금 |

계좌 간 이체 예정은 예측에서도 뺀다. 회사 전체 돈은 그대로이기 때문이다.

## 4. 2단계: 최근 20영업일 평균 구하기

**왜 10/2부터인가?** 10월 영업일은 21일이다. 주말과 10/9 한글날을 빼서 그렇다. 그중 최근 20일이 **10/2~10/30**이다.

1편에서 M열에 붙인 자금코드로, 10/2 이후 실적을 코드별로 뽑았다.
```
=SUMIFS(bank_transactions!I:I, bank_transactions!M:M, "매출대금 회수", bank_transactions!E:E, ">="&J5)
```
- `bank_transactions!` = 다른 시트를 볼 때 붙이는 "그 시트의"
- `">="&J5` = J5 날짜 이후 (1편의 `"<"&P1`과 같은 원리)

**10/2~10/30 실적 (순액)**

| 자금코드 | 실적 |
|---|---:|
| 매출대금 회수 | 1,464,620,000 |
| 카드매출 정산 | 102,686,900 |
| 원재료 매입 | −543,280,000 |
| 운영비 | −25,042,300 |
| 세금·4대보험 | −101,517,000 |
| 카드결제대금 | −23,480,500 |
| 차입금 | 300,000,000 |
| 대출 이자·상환 | −51,575,000 |
| 확인 필요 | 5,000,000 |
| 임차료 | −12,100,000 |
| 급여 | −128,750,000 |

**하루 평균 3개**
```
=ROUND(합계/20, -5)     ← -5 = 10만 원 단위 반올림
```
| 묶음 | 20일 합계 | 하루 평균 |
|---|---:|---:|
| 매출 (매출대금 회수 + 카드매출 정산) | 1,567,306,900 | **78,400,000** |
| 원재료 매입 | 543,280,000 | **27,200,000** |
| 운영비 | 25,042,300 | **1,300,000** |

📷 `02_2단계_10월실적_평균구하기.png`

### 🚧 시행착오 ①: 작은 실수 세 개
- **원재료 평균에 반올림이 빠졌다.** −27,164,000이 나왔다. → `ROUND(…, -5)`로 감쌌다.
- **출금 평균을 마이너스로 뒀다.** 잔액 공식이 `입금 − 출금`인데 출금이 이미 마이너스면 **두 번 빼게 된다.** → 플러스로 바꿨다.
- **실적 합계에 "확정수입 금액"이라고 이름을 붙였다.** 예측에서는 말을 꼭 구분해야 한다.
  - **확정(예정)** = 앞으로 일어나기로 약속된 돈 → `cash_schedule`
  - **실적** = 이미 일어난 돈 → `bank_transactions`

### 🚧 시행착오 ②: 세금도 평균을 냈다
세금·4대보험 평균도 구했다. 101,517,000 ÷ 20 ≈ 5,100,000이다. 계산은 맞다. 그런데 스킬은 매출, 원재료, 운영비 **3개만** 평균을 낸다. 왜일까?

> **내 답**
> 1. 세금은 10/12, 부가세는 10/26에 나갔다. **나가는 날이 정해져 있다.**
> 2. 매일 5,100,000씩 빼면, 아직 세금이 안 나간 날에도 현금이 부족한 것처럼 잘못 보일 수 있다.

여기에 하나가 더 있다. 11/10에는 예정표에 세금 33,200,000이 **이미 있다.** 매일 평균도 빼고 예정도 빼면 **같은 돈을 두 번 빼게 된다.**

**📌 정리: 매일 나가는 것과 아닌 것**
- **매일 나가는 것 (평균):** 원재료 매입, 운영비 (+ 입금은 매출)
- **정해진 날 나가는 것 (예정표):** 세금·4대보험, 카드대금, 급여, 임차료, 대출 이자·상환
- **빼는 것:** 계좌 간 이체, 확인 필요, 대출 실행처럼 가끔 크게 있는 것

### 🔍 발견: 예정표에서 빠진 세금
"11/13에 세금을 다시 넣어야 하지 않아?"라고 물었다. 11/13은 세금이 아니라 **카드대금**이었다. 세금은 매달 10일에 한 번만 나가고, 부가세는 분기마다 나간다.

그런데 이 질문 덕분에 10월 실적과 11월 예정표를 나란히 놓고 봤더니, 빠진 게 하나 있었다.

| 10/12 실제로 나간 것 | 11/10 예정표 |
|---|---|
| 원천세 14,620,000 | 원천세 14,900,000 ✅ |
| **지방소득세 1,462,000** | **❌ 없음** |
| 국민연금 + 건강보험 18,095,000 | 국민연금·건강보험 18,300,000 ✅ |

> 💡 **예측은 예정표만큼만 정확하다.** 예정표를 지난달 실적과 대조해서 빠진 항목을 찾는 것이 자금 담당자의 일이다. (지방소득세는 원천세의 10%라 약 1,490,000으로 짐작된다.)

## 5. 3단계: 예측표 만들기

새 시트 `예측표`를 만들었다. 최종 배치는 이렇다.

| A | B | C | D | E | F | G | H | J |
|---|---|---|---|---|---|---|---|---|
| 날짜 | 예정 입금 | 평균 입금 | 예정 출금 | 매입대금 (도우미) | 평균 출금 (원재료) | 평균 출금 (운영비) | 예상 잔액 | 특이사항 |

### 날짜: 주말 빼고 채우기
11/2~11/13 중 영업일만 필요하다. 하나씩 치지 않고 이렇게 했다.
- **방법 1:** A2에 `2026-11-02`를 넣고 채우기 핸들로 끌어 내린 뒤 → **자동 채우기 옵션 → "평일 단위 채우기"**
- **방법 2:** `=WORKDAY(A2, 1)` → "다음 영업일". 휴일까지 빼려면 `=WORKDAY(A2, 1, 휴일범위)`

### B열·D열: 예정 금액
1단계 수식에 **날짜 조건 하나만** 더 붙였다.
```
B2: =SUMIFS(cash_schedule!$F:$F, cash_schedule!$B:$B, A2, cash_schedule!$C:$C, "입금", cash_schedule!$D:$D, "<>*내부이체*")
D2: (같은 수식에서 "입금" → "출금")
```

#### 🚧 시행착오 ③: 따옴표 하나
```
❌ …cash_schedule!D:D,"<>*내부이체*)
✅ …cash_schedule!D:D,"<>*내부이체*")
```
닫는 `"`가 없어서 엑셀이 `)`까지 글자로 읽었다. 수식이 끝나지 않아 셀이 편집 상태로 멈췄다.
> 💡 수식 안의 `"` 개수는 **항상 짝수**여야 한다.

📷 `03_시행착오_따옴표빠짐.png`

### C열: 평균 입금 (매출)
> 규칙: 그날 예정 매출이 있으면 0, 없으면 78,400,000

#### 🚧 시행착오 ④: 예정 금액을 20으로 나눴다
처음에는 `=ROUND(D2/20, -5)`처럼 **예정 금액을 20으로 나눴다.** 그런데 "÷ 20"은 2단계에서 이미 끝난 일이다. 20일 치 실적을 하루치로 바꾼 것이다. 예정 금액은 **이미 그날 하루치**다. 평균 칸에는 2단계의 하루 평균을 **가져다 놓기만** 하면 된다.

📷 `04_시행착오_예정금액을_20으로나눔.png`

그래서 처음부터 천천히 다시 했다. 수식 없이 "0이 될 날과 78,400,000이 될 날"을 먼저 손으로 생각했다.

#### 🚧 시행착오 ⑤: 두 번 세기
```
❌ =IF(B2>0, B2, cash_schedule!$M$7)    ← 예정이 있으면 예정 금액을 넣음
✅ =IF(B2>0, 0,  cash_schedule!$M$7)    ← 예정이 있으면 0
```
"그날 매출로 잡을 금액 = 약속이 있으면 약속, 없으면 평균"이라는 생각 자체는 맞았다. 하지만 이 표는 **B(약속)와 C(짐작)를 둘 다 더한다.** 그래서 11/2 한결마트 84,000,000이 **두 번** 들어간다(168,000,000).

📷 `05_시행착오_C열_두번세기.png`

### E·F·G열: 평균 출금 (원재료 + 운영비)
> 규칙: 그날 예정표에 **매입대금**이 있으면 원재료는 0. 운영비는 **매일 무조건**.

#### 🚧 시행착오 ⑥: D열을 조건으로 썼다
```
❌ =IF(D2>0, 0, SUM(원재료 평균 + 운영비 평균))
```
문제가 두 개였다.
1. **D열에는 원재료만 있는 게 아니다.** 11/10은 세금, 11/13은 카드대금이다. 세금 내는 날에도 원재료는 산다.
   > 🛒 "오늘 **전기요금** 내는 날이니까 **장 보기는 안 한다**"는 말이 안 된다.
2. **운영비까지 같이 0이 됐다.** 운영비는 예정표에 아예 없어서 겹칠 일이 없다.
   > 🛒 장을 미리 주문해 둔 날이라도 **점심 식대는 매일** 나간다.

📷 `06_시행착오_E열_D열조건함정.png`

**해결: 열을 쪼갰다.** 원재료(F)와 운영비(G)를 나누고, "매입대금인가?"를 묻는 **도우미 열(E)**을 만들었다. 1편의 LOOKUP을 도우미 열로 쪼개서 이해한 것과 같은 방법이다.
```
E2 (예정 매입 건수): =COUNTIFS(cash_schedule!$B:$B, A2, cash_schedule!$D:$D, "*매입대금*")
F2 (원재료 평균):    =IF(E2>0, 0, cash_schedule!$M$8)
G2 (운영비 평균):    =cash_schedule!$M$9
```
→ 11/3만 E=1, F=0이고 나머지 날은 F=27,200,000이다. G는 매일 1,300,000이다.

📷 `07_도우미열로_원재료_운영비_나누기.png`

## 6. 4단계: 잔액 이어 붙이기

자금일보 공식을 그대로 썼다.
```
H2: =bank_accounts!G5 + SUM(B2:C2) - SUM(D2, F2:G2)
H3: =H2 + B3 + C3 - D3 - F3 - G3     (아래로 채우기)
```
- H2의 출발점은 숫자로 직접 치지 않고 **10/30 실제 잔액 합계 칸(`bank_accounts!G5`)**에 연결했다. 실제 잔액이 바뀌면 예측도 따라 바뀐다.
- `SUM(D2, F2:G2)`에서 **E열(도우미 1)은 뺐다.** E를 넣으면 11/3에 1원이 더 빠진다.

| 10/30 (실제) | | | | | | 2,895,280,500 |

## 8. 생각해 본 것 두 가지 (토론)

### ① 현금주의 예측은 비회계적일까?
> **처음 생각:** 현금주의로 계산하는 게 비회계적이긴 하지만, 넓게 보면 발생주의와 거의 차이가 나지 않는다.

**다시 생각해 보니:** 이 회사만 봐도 차이가 크다.

| 10월 현금 흐름 | 현금 | 손익(발생주의) |
|---|---:|---|
| 10/16 대출 실행 | +300,000,000 | 수익 아님 (부채) |
| 10/26 부가세 납부 | −67,340,000 | 비용 아님 (부가세예수금 정산) |
| 10/30 원금 상환 | −50,000,000 | 비용 아님 (부채 감소) |
| 10/19 원재료 매입 186,500,000 | 지금 나감 | 팔릴 때 비용 (재고) |
| 11/2 한결마트 "10월분" 매출대금 | 11월에 들어옴 | 10월 매출 |

그리고 현금 기준은 비회계적인 게 아니라 **목적이 다를 뿐**이다.
- **발생주의**는 "얼마나 벌었나"(손익)를 본다.
- **현금주의**는 "그날 지급할 돈이 통장에 있나"(유동성)를 본다.

현금흐름표도 재무제표의 하나다. 흑자인데 현금이 없어 쓰러지는 **흑자도산**이 바로 이 차이에서 생긴다.

### ② 급여 통장(A2)은 예측할 수 없을까?
> **처음 생각:** 급여 5일 전에 NH(급여 통장)로 얼마를 이체할지는 이사회 권한이라 A2는 예측할 수 없다. 하지만 총 현금흐름이 늘고 있으니 급여는 충분하다고 예측할 수 있다.

**다시 생각해 보니:** 이체 금액을 **결정하는 것**은 결재권자의 일이다. 하지만 결정하려면 "얼마가 필요한지"라는 숫자가 있어야 한다. **그 숫자를 만드는 것이 예측이다.** (참고로 자기 회사 계좌 간 이체는 보통 이사회보다는 전결규정상 자금팀장이나 CFO 선에서 정한다. 회사마다 규정을 따르면 된다.)

"추가 이체가 없다면"이라고 가정하고 A2를 예측해 봤다.

| A2(농협, 급여·세금 통장) | 금액 |
|---|---:|
| 10/30 잔액 | 165,933,000 |
| 11/10 예정 이체 (A1 → A2) | +40,000,000 |
| 11/10 원천세·4대보험 | −33,200,000 |
| 11/10 지방소득세 (예정표에 없음) | −약 1,490,000 |
| 11/25 급여 | −128,750,000 |
| **남는 돈** | **약 42,500,000** |

- **결론:** 예정된 40,000,000 이체만 승인되면 급여까지 충분하다. 추가 이체는 필요 없다.
- 40,000,000 이체가 승인되지 않으면 남는 돈은 **약 250만 원**이다. → "이체 승인이 꼭 필요하다"고 보고해야 한다.

> 💡 **"전체 현금이 충분하다 ≠ 급여 통장이 충분하다."** 32억 원이 있어도 급여일에 그 통장에 돈이 없으면 급여는 못 나간다. 예측은 결정을 대신하는 게 아니라, **결정에 필요한 숫자(얼마를, 언제까지)**를 주는 일이다.

## 9. 해 보고 느낀 점

- **예측 = 확정된 약속 + 평소의 평균.** 원리는 한 줄인데, "평균을 언제 빼나"가 제일 어려웠다.
- **두 번 세기가 가장 흔한 실수다.** 예정과 평균이 겹치는 날, 같은 돈이 두 번 들어가거나 나간다.
- **"매일 나가는 것"과 "정해진 날 나가는 것"을 나누는 게 핵심이다.** 세금, 급여, 이자는 평균을 내면 안 된다.
- **예측은 예정표만큼만 정확하다.** 지난달 실적과 대조하다 지방소득세 누락을 찾았다.
- **지난달 날짜를 베끼면 안 된다.** 10월에 12일, 26일에 나간 건 주말 때문이었다.
- **조건은 정확히 그 대상만 봐야 한다.** "출금이 있는 날"이 아니라 "**원재료** 약속이 있는 날"이다.
- **어려우면 열을 쪼갠다.** 도우미 열 하나로 복잡한 IF가 단순해졌다.
- **현금 기준은 유동성을 보는 도구다.** 손익과 다르고, 그래서 따로 필요하다.
- **회사 전체가 아니라 통장별로** 봐야 하는 순간이 있다. 급여 통장이 그렇다.
